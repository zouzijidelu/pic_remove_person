## 1. 对比口径

三种模型都接在同一条链路上，只换填洞后端：

```
全景（约 5376×2688 / 6720×3360）
  → SAM / 矩形框 / 笔刷  →  原尺寸 Mask
  → 选修复模型
  → 只在 Mask 区域贴回原分辨率
```

| 规则 | 说明 |
|------|------|
| Mask 相同 | 不重新涂，避免「模型不同、Mask 也不同」 |
| 扩散类只跑 ROI | 按 Mask 外扩约 256px 后最长边缩到 ≤768，禁止喂整幅全景 |
| 贴回 | 模型可改整块 ROI，主进程只把 Mask 内像素写回 |
| LaMa vs PowerPaint 图 | `iopaint-bench/out/sheets/`，评测日期约 2026-08-17 |
| Qwen | 旁路 worker、协议、NF4 配置已落地；**无同 Mask 输出图** |

样例来源：`验证识别人像后直接消除效果/output/有人图/选用/`（6 个 case）。

## 2. 工程对比（三种都已接入 Demo）

| 维度 | LaMa | PowerPaint | Qwen-Edit-2511 |
|------|------|------------|----------------|
| 角色 | 默认、日常 | 难例旁路 | 指令编辑旁路（试验） |
| 跑在哪 | Demo `.venv` 本进程 | `iopaint-bench` 独立 worker | `qwen-edit-bench` 独立 worker |
| 原理 | 空洞纹理填补 | SD Inpaint + object-remove | 文生图式改图 + prompt |
| 输入 | 整图降采样（最长边 ≤2048） | ROI + Mask | ROI + prompt（有 mask 则传入） |
| 权重体积 | ~196MB | ~4GB | NF4 约 15GB+（BF16 ~40GB，3090 不能上） |
| 3090 显存 | SAM+LaMa 合计约 3～4GB | 再加约 4～8GB | NF4 约 16～20GB，须与 PowerPaint **互斥** |
| 本机 Mac | CPU 可日常用 | MPS 可用，**不要与 SAM 同时预热**，否则易把整机打崩 | 真模型不能跑；仅 dry-run 验协议 |
| 首次加载 | 秒级 | 1～2 分钟 | 未预下载时可能 >30 分钟（界面 1800s 会超时） |
| 单次推理（129 实测） | GPU 2.6s，handler ~4s（2048） | ROI handler ~7s（768） | 未测（计划 20 步） |
| 点击到出图 | 另加 Gradio 发 6720 JPEG，体感可接近 PowerPaint | 同上后半段 | 未测 |
| 启动预热 | 建议预热 | 本机不建议；与 Qwen 共存时不预热 | 默认不预热（`WARMUP_QWEN=0`） |
| 许可证 | 现有依赖 | IOPaint 1.6.0 / PowerPaint | Apache-2.0 |

接入方式（不要混装 venv）：

```
消除人像/app.py          SAM + 界面 + 贴回
backends/lama.py         本进程
iopaint-bench/           PowerPaint worker
qwen-edit-bench/         Qwen worker
```

## 3. 视觉对比：LaMa vs PowerPaint（已实测）

对照图列：`orig | mask | iopaint_lama | powerpaint`。

| Case | 场景类型 | LaMa | PowerPaint | 更适合 |
|------|----------|------|------------|--------|
| `826149651_location_01` | 近景站立人 + 门口远处人 | 三人消除干净，门口结构还在，人体处略糊 | 近景处编出畸形「残影人」 | **LaMa** |
| `913987625_location_01` | 近景大面积人体（遮柜门） | 人去掉，柜门/墙被抹成糊斑 | 更清晰，但编出新隔板/圆镜，语义不对 | 都不理想；展示优先 LaMa |
| `504968637_location_04` | 床沿坐着的两人（大 Mask） | 大片灰褐糊斑 | 纹理更好，但床上编出异物 | 大面积人：**都不宜直接上线** |
| `826126046_location_12` | 多人 + 前景走动人 | 墙地被纵向涂抹，立面变形 | 墙地更利落，中间区域会编家具 | 结构上 PowerPaint 更好，需人工过目 |
| `826117721_location_02` | 餐桌多人 + 前景运动残影 | 大块平滑污渍 | 有纹理，大 Mask 里会塞进错误物体 | 大 Mask：**两者都差** |
| `913980277_location_09` | 门口弯腰人 + 坐姿成人小孩 | 糊斑明显 | 地面/墙线更连贯，被挡家具能补出来 | 该例 **PowerPaint 更好** |

跨 6 张的稳定规律：

1. **小面积、远处人、门口缝：** LaMa 更稳，很少编出新人。  
2. **大面积近景人、运动残影：** 两者都差。LaMa 糊，PowerPaint 更容易「编内容」。  
3. **结构线（门框、立柱、地砖）：** PowerPaint 往往更直、更锐。  
4. PowerPaint 的失败模式是 **幻觉**（新人、新家具），不是单纯模糊。房源图里幻觉比轻度发糊更不能接受。

## 4. Qwen-Image-Edit-2511：已完成与未完成

### 已完成（工程）

- 独立仓库 `qwen-edit-bench`，JSON 行协议与 PowerPaint worker 同类  
- Demo 注册 `Qwen-Edit`，ROI + `paste_roi`，不改 SAM  
- 130 上独立 `.venv`：`torch 2.13.0+cu130`、`bitsandbytes 0.50.1`、`QwenImageEditPlusPipeline` 可导入  
- `smoke_cpu.py` 协议通过  
- 与 PowerPaint **互斥释放显存**；Qwen 默认不随服务预热  

### 未完成（效果）

| 时间 | 事件 |
|------|------|
| 2026-08-19 约 13:14 | 界面点 Qwen-Edit，开始加载 `seochan99/Qwen-Image-Edit-2511-bnb-nf4` |
| +1800s | worker 未返回 `ready`，Demo 超时（权重未预下载，进度条被关掉） |
| 随后 | `nvidia-smi` 失效；`lspci` 只剩基板 Matrox，3090 从 PCIe 消失 |
| 运维 | 认定显卡硬件故障（slot 8 总线 fatal 在 8/16、8/18 已出现），停机维修 |

因此：**不能根据一次超时判断 Qwen 画质。** 指令编辑模型理论上可能比 LaMa 更懂「去掉人、补墙地」，也可能像 PowerPaint 一样编出新人。必须在 GPU 恢复后用 **同一 6 张 Mask** 出图再下结论。

Qwen 恢复后的最低评测清单：

1. 冷启动确认 `nvidia-smi` 有 3090  
2. `HF_ENDPOINT=https://hf-mirror.com` 预下载 NF4，不要走 Gradio 第一次加载  
3. `WARMUP_QWEN=0`，不要与 PowerPaint 同时常驻  
4. 同一 ROI 出图，把 Qwen 列进 `iopaint-bench` 对照表  
5. 重点看：门口结构、大面积人、近景人是否编内容

## 5. 资源与稳定性

| 环境 | 现象 | 建议 |
|------|------|------|
| 本机 Mac | SAM + LaMa + PowerPaint 同时预热，再对 6720 全景做矩形框 SAM，可能整机崩溃 | `ENABLE_POWERPAINT=0` 标完再用 PowerPaint；或启动不预热 PowerPaint；ROI ≤768 |
| 130 RTX 3090 | BF16 装不下；NF4 需约 16～20GB；与 PowerPaint 互斥 | 默认 LaMa；Qwen/PowerPaint 按需加载 |
| 130 硬件 | 修卡前不要再点 Qwen、不要重装驱动 | 等 `lspci` 出现 `10de` 后再测 |

## 6. 推荐策略（业务）

| 场景 | 模型 | 理由 |
|------|------|------|
| 默认 / 产线候选 | **LaMa** | 快、稳、少幻觉、本机和 GPU 都能跑 |
| 门口、柜门、地砖结构糊了 | **PowerPaint**（人工切一次） | 结构更好；必须人工看有没有编出人/家具 |
| 大面积近景人、床上坐人、运动残影 | 先精修 Mask，仍差则 **不要自动过扩散模型** | 两家都容易失败 |
| Qwen | 仅试验 | 效果未验证；权重与显存成本高 |

产品形态维持已有共识：Gradio 只做 Demo；生产对外一个 API，对内 LaMa 本进程 / 扩散模型分进程。
