## 1. 目录与三个仓库（与 130 一致，不要再套父目录）

和 130 一样，三个仓库直接放在 `/root` 下并列，**不要**再包一层文件夹：

```
/root/pano-inpaint      # Demo，Git: pic_remove_person
/root/iopaint-bench     # PowerPaint worker
/root/qwen-edit-bench   # Qwen worker
```

三个 **独立 `.venv`**，禁止互相 `pip install`。

```bash
cd /root
git clone git@github.com:zouzijidelu/pic_remove_person.git pano-inpaint
git clone git@github.com:zouzijidelu/iopaint-bench.git
git clone git@github.com:zouzijidelu/qwen-edit-bench.git
```

SSH 不可用时用 HTTPS：

```bash
cd /root
git clone https://github.com/zouzijidelu/pic_remove_person.git pano-inpaint
git clone https://github.com/zouzijidelu/iopaint-bench.git
git clone https://github.com/zouzijidelu/qwen-edit-bench.git
```

本机若还有未推送的 Demo 改动（PowerPaint/Qwen 共存时不预热），**先在 Mac 上 push `pic_remove_person`，再在 129 上 clone/pull**。否则 129 仍会启动时预热 PowerPaint。

### GitHub SSH（HTTPS 经常失败时用这个）

国内机访问 `https://github.com` 经常超时。SSH 走 22 也可能被墙，**优先用 443 端口的 SSH**。

在 **129** 上：

```bash
# 已有密钥就跳过生成
ls -l ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519 -C "pano-lama-129" -f ~/.ssh/id_ed25519 -N ""

cat ~/.ssh/id_ed25519.pub
```

把公钥整行贴到 GitHub：右上角头像 → **Settings** → **SSH and GPG keys** → **New SSH key**（账号需对 `zouzijidelu/*` 有权限）。

强制走 443，避免 22 不通：

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
cat >> ~/.ssh/config <<'EOF'
Host github.com
  HostName ssh.github.com
  User git
  Port 443
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config
ssh-keyscan -p 443 ssh.github.com >> ~/.ssh/known_hosts 2>/dev/null || true
ssh -T git@github.com
```

期望：`Hi zouzijidelu! You've successfully authenticated...`（名字以 GitHub 账号为准）。问 `yes/no` 时输入 `yes`。

已用 HTTPS clone 过的仓库改成 SSH：

```bash
cd /root/pano-inpaint
git remote set-url origin git@github.com:zouzijidelu/pic_remove_person.git
git remote -v
git pull
```

另外两个仓库同样改：

```bash
cd /root/iopaint-bench
git remote set-url origin git@github.com:zouzijidelu/iopaint-bench.git
cd /root/qwen-edit-bench
git remote set-url origin git@github.com:zouzijidelu/qwen-edit-bench.git
```

不要把 `id_ed25519` **私钥**发到聊天或提交进 Git。公钥（`.pub`）可以贴。

## 2. 部署 Demo（LaMa + SAM）

```bash
export HF_ENDPOINT=https://hf-mirror.com
cd /root/pano-inpaint
chmod +x deploy_server.sh setup.sh start.sh
bash deploy_server.sh
```

若报 `pyenv: python3.12: command not found`（shim 存在但未指向具体版本），指定真实解释器：

```bash
export PYTHON_BIN=/root/.pyenv/versions/3.12.11/bin/python
"$PYTHON_BIN" --version
SKIP_APT=1 bash deploy_server.sh
```

路径不对就 `ls /root/.pyenv/versions/3.12.*/bin/python` 换成实际文件。不要用名为 `deepseek` / `da-2` 的现成环境。

脚本会：建 Python 3.12 venv、装 CUDA torch、写 `server.env`、注册 systemd **`pano-lama`**、监听 **7860**。

```bash
journalctl -u pano-lama -f
```

等到 `Running on` / `[warmup] 完成`。浏览器：`http://10.2.143.129:7860`。先只用 **LaMa** 消一张，确认 GPU 正常。

### 若卡在 `[sam] downloading checkpoint` 超过几分钟

这不是 Qwen，也不是 PowerPaint。`app.py` 从 Facebook CDN 拉 **约 375MB** 的 `sam_vit_b_01ec64.pth`，国内机器经常 **无进度挂死**（`urllib` 不打进度、也没超时）。20 分钟仍停在同一行就不正常。

先看文件有没有在涨：

```bash
ls -lh /root/pano-inpaint/.cache/sam/
watch -n 2 'ls -lh /root/pano-inpaint/.cache/sam/'
```

`.pth.partial` 为 0 或不涨：停服务，改从国内源下，再启动。

```bash
systemctl stop pano-lama
mkdir -p /root/pano-inpaint/.cache/sam
rm -f /root/pano-inpaint/.cache/sam/*.partial \
      /root/pano-inpaint/.cache/sam/sam_vit_b_01ec64.pth

# 优先魔搭；失败再试 hf-mirror
cd /root/pano-inpaint/.cache/sam
wget -c -O sam_vit_b_01ec64.pth \
  "https://www.modelscope.cn/models/AI-ModelScope/sam-vit-base/resolve/master/sam_vit_b_01ec64.pth" \
  || wget -c -O sam_vit_b_01ec64.pth \
  "https://hf-mirror.com/ybelkada/segment-anything/resolve/main/checkpoints/sam_vit_b_01ec64.pth"

ls -lh sam_vit_b_01ec64.pth
# 应约 358M（大于 300MB 才算有效）
systemctl start pano-lama
journalctl -u pano-lama -f
```

期望很快出现 `[sam] loading ViT-B` → `[warmup] 完成`。`ENABLE_QWEN_EDIT=0` 此时是对的，先把 Demo 跑起来。

## 3. 加 PowerPaint

```bash
cd /root/pano-inpaint
bash deploy_powerpaint.sh
```

要求 `/root/iopaint-bench/inpaint_worker.py` 已在。PowerPaint 用 **Python 3.11** 旁路 venv（不要用 Demo 的 3.12）。没有 3.11 时脚本会落到 3.12，`iopaint` 可能从 **pypi.org 再下一份 torch（500MB+）**，几十 kB/s 会卡一个多小时。

若已经很慢（正在下 `torch-2.13.0`），**Ctrl+C**，改成先装 CUDA torch、再装 iopaint：

```bash
# 优先 3.11；没有再用 3.12 的真实路径，不要 pyenv 的 python3.12 shim
export PYTHON=/usr/bin/python3.11
# 或：export PYTHON=/root/.pyenv/versions/3.12.11/bin/python

cd /root/iopaint-bench
rm -rf .venv
"$PYTHON" -m venv .venv
.venv/bin/python -m pip install -U pip -i https://pypi.tuna.tsinghua.edu.cn/simple
.venv/bin/python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
# 上面也慢则改：--index-url https://mirrors.aliyun.com/pytorch-wheels/cu124/

.venv/bin/python -m pip install "iopaint==1.6.0" \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  --extra-index-url https://pypi.org/simple

.venv/bin/python -c "import torch, iopaint; print(torch.__version__, torch.cuda.is_available())"

cd /root/pano-inpaint
SKIP_SETUP=1 bash deploy_powerpaint.sh
```

`SKIP_SETUP=1` 只写 `server.env` 并重启服务，不再重装依赖。

`server.env` 会被写成：

```
ENABLE_POWERPAINT=1
POWERPAINT_DEVICE=cuda
POWERPAINT_MAX_SIDE=768
IOPAINT_BENCH=/root/iopaint-bench
```

界面出现 PowerPaint 后，**第一次点才会加载约 4GB**（若未预热），约 1～2 分钟，之后进程常驻会快很多。

Qwen 还没开时，启动会 **预热 PowerPaint**。日志停在 `Downloading model from Huggingface` 且只有 `FutureWarning` 是正常的：进度条被关掉了，`journalctl` 也不显示 tqdm。网页要等 `[warmup] 完成` 才会监听 7860。

```bash
du -sh /root/iopaint-bench/.cache/huggingface
watch -n 5 'du -sh /root/iopaint-bench/.cache/huggingface'
ss -lntp | grep 7860 || true
```

几分钟内 `du` 在涨就等。一直不涨则停服务，用镜像预下载后再启动。

**不要**在下载失败后立刻 `systemctl start pano-lama`：服务会再走一遍无进度下载，网页仍然起不来。也**不要删缓存**，差几十 MB 断线可以续传。

若日志出现 `us-aws.cdn.hf.co` 或 `IncompleteRead`：只设 `HF_ENDPOINT` 不够，大文件仍会跳到 AWS CDN。先停服务，关掉 Xet，单线程续传：

```bash
systemctl stop pano-lama
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/root/iopaint-bench/.cache/huggingface
export HF_HUB_CACHE=/root/iopaint-bench/.cache/huggingface/hub
export HF_HUB_DISABLE_XET=1
export HF_HUB_ENABLE_HF_TRANSFER=0
export HF_HUB_DOWNLOAD_TIMEOUT=300

/root/iopaint-bench/.venv/bin/python - <<'PY'
import os
os.environ["HF_HUB_DISABLE_XET"] = "1"
os.environ["HF_ENDPOINT"] = "https://hf-mirror.com"
from huggingface_hub import snapshot_download
p = snapshot_download(
    "Sanster/PowerPaint-V1-stable-diffusion-inpainting",
    max_workers=1,
    resume_download=True,
)
print("ok", p)
PY
```

进度条里的 URL 应是 `hf-mirror.com`，不应再出现 `us-aws.cdn.hf.co`。打印 `ok` 后再：

```bash
systemctl start pano-lama
journalctl -u pano-lama -f
```

Python 仍跳 AWS 或再次 `IncompleteRead` 时，用镜像的 aria2：

```bash
systemctl stop pano-lama
apt-get install -y aria2
cd /tmp
wget -qO hfd.sh https://hf-mirror.com/hfd/hfd.sh
chmod +x hfd.sh
export HF_ENDPOINT=https://hf-mirror.com
./hfd.sh Sanster/PowerPaint-V1-stable-diffusion-inpainting --tool aria2c -x 8
```

`hfd.sh` 默认下到当前目录时，再按它打印的路径核对；目标是让 `/root/iopaint-bench/.cache/huggingface` 里有完整模型。不确定时把 `HF_HOME` 指到同一处再跑一遍上面的 `snapshot_download`（已有文件会秒过）。

### 若 journalctl 出现 `the: command not found`（exit 127 循环）

PowerPaint 的 `.venv` 已经装好了，**不是依赖问题**。`start.sh` 会加载 `server.env`；`QWEN_EDIT_PROMPT` 里有空格且没加引号时，bash 把 `the` 当成命令，服务立刻退出。

在 129 上立刻修（不必等 git pull）：

```bash
sed -n '1,20p' /root/pano-inpaint/server.env
sed -i 's|^QWEN_EDIT_PROMPT=.*|QWEN_EDIT_PROMPT="Remove the person. Reconstruct the background only. Do not add new people."|' /root/pano-inpaint/server.env
grep '^QWEN_EDIT_PROMPT=' /root/pano-inpaint/server.env
systemctl restart pano-lama
journalctl -u pano-lama -n 40 --no-pager
```

期望：不再出现 `command not found`，出现 `启动全景人像消除 Demo → http://0.0.0.0:7860`。然后打开 `http://10.2.143.129:7860`。

## 4. 加 Qwen-Edit（L20 46GB 可以开；仍用 NF4，先预下载）

### 4.1 环境

清华源经常没有新版 `diffusers` / `bitsandbytes`。仓库里 `setup.sh` 会回退官方 PyPI。一律用 **`.venv/bin/python`**，不要只 `source activate` 后又退回 conda `(base)`。

```bash
cd /root/qwen-edit-bench
export HF_ENDPOINT=https://hf-mirror.com
chmod +x setup.sh
./setup.sh
.venv/bin/python -c "import torch; from diffusers import QwenImageEditPlusPipeline; print(torch.__version__, torch.cuda.is_available())"
.venv/bin/python smoke_cpu.py
```

期望：`True`，以及 `smoke_cpu ok`。

若 `bitsandbytes` 仍失败：

```bash
cd /root/qwen-edit-bench
.venv/bin/python -m pip install bitsandbytes -i https://pypi.org/simple
```

### 4.2 先预下载权重（不要用网页第一次加载）

130 上 Gradio 等 1800s 超时，下载被杀掉，随后 GPU 掉总线。129 上 **必须先下完再点界面**。

```bash
cd /root/qwen-edit-bench
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/root/qwen-edit-bench/.cache/huggingface
.venv/bin/python - <<'PY'
from huggingface_hub import snapshot_download
p = snapshot_download("seochan99/Qwen-Image-Edit-2511-bnb-nf4")
print("ok", p)
PY
```

下完再：

```bash
cd /root/pano-inpaint
bash deploy_qwen_edit.sh
```

写入：

```
ENABLE_QWEN_EDIT=1
QWEN_EDIT_DEVICE=cuda
QWEN_EDIT_MAX_SIDE=768
QWEN_EDIT_BENCH=/root/qwen-edit-bench
QWEN_EDIT_DRY_RUN=0
WARMUP_QWEN=0
WARMUP_POWERPAINT=0
```

### 4.3 第一次点 Qwen

另开终端：

```bash
journalctl -u pano-lama -f
watch -n 1 nvidia-smi
```

日志应有 `worker ready`，**不应**再出现 1800s 超时。PowerPaint 与 Qwen 会互斥卸载，不要两个一起预热。
