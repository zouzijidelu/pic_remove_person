# 129 机重新部署与启用说明

| 项目 | 内容 |
|------|------|
| 日期 | 2026-08-19 |
| 原机器 | `10.2.143.130`（qh-vr-gpu-143-130），显卡硬件故障，停机维修 |
| 新机器 | `10.2.143.129`（JumpServer：`qh-test-linshi-gpu-143-129`） |
| 登录 | 堡垒机 SSH（密钥 `super_user`）→ `sudo -i` |
| 访问 | 部署成功后内网 `http://10.2.143.129:7860` |

本文按 130 上已跑通的结构，在 129 **从零部署** Demo + PowerPaint + Qwen。不要从 130 拷 `.venv` 或损坏的 GPU 缓存。

---

## 0. 先确认 GPU（不过这一步不要装任何模型）

```bash
sudo -i
nvidia-smi
lspci -nn | grep -i 10de
df -h /
uname -r
```

必须同时满足：

- `nvidia-smi` 能看到独显（型号、显存）
- `lspci` 有 NVIDIA（`10de`）
- 根分区建议空余 **≥40GB**（Qwen NF4 约 15GB+，另加 LaMa/SAM/PowerPaint）

不满足就停，联系运维。**不要**在认不到卡时重装驱动。

显存建议：

| 显存 | 怎么开 |
|------|--------|
| 24GB（3090 同类） | LaMa + SAM 常驻；PowerPaint / Qwen **互斥、按需加载**；Qwen 用 NF4，不要 BF16 |
| 16GB | 可开 LaMa + PowerPaint；Qwen 先不要开，或开 `cpu_offload`（会很慢） |
| 12GB 及以下 | 只开 LaMa；不要上 Qwen |

129 的卡型以 `nvidia-smi` 为准，不要默认它和 130 一样。

## 1. 目录与三个仓库（与 130 一致，不要再套父目录）

和 130 一样，三个仓库直接放在 `/root` 下并列，**不要**再包一层文件夹：

```
/root/pano-inpaint      # Demo，Git: pic_remove_person
/root/iopaint-bench     # PowerPaint worker
/root/qwen-edit-bench   # Qwen worker
```

三个 **独立 `.venv`**，禁止互相 `pip install`。

```bash
cd /root
git clone git@github.com:zouzijidelu/pic_remove_person.git pano-inpaint
git clone git@github.com:zouzijidelu/iopaint-bench.git
git clone git@github.com:zouzijidelu/qwen-edit-bench.git
```

SSH 不可用时用 HTTPS：

```bash
cd /root
git clone https://github.com/zouzijidelu/pic_remove_person.git pano-inpaint
git clone https://github.com/zouzijidelu/iopaint-bench.git
git clone https://github.com/zouzijidelu/qwen-edit-bench.git
```

本机若还有未推送的 Demo 改动（PowerPaint/Qwen 共存时不预热），**先在 Mac 上 push `pic_remove_person`，再在 129 上 clone/pull**。否则 129 仍会启动时预热 PowerPaint。

## 2. 部署 Demo（LaMa + SAM）

```bash
export HF_ENDPOINT=https://hf-mirror.com
cd /root/pano-inpaint
chmod +x deploy_server.sh setup.sh start.sh
bash deploy_server.sh
```

脚本会：建 Python 3.12 venv、装 CUDA torch、写 `server.env`、注册 systemd **`pano-lama`**、监听 **7860**。

```bash
journalctl -u pano-lama -f
```

等到 `Running on` / `[warmup] 完成`。浏览器：`http://10.2.143.129:7860`。先只用 **LaMa** 消一张，确认 GPU 正常。

---

## 3. 加 PowerPaint

```bash
cd /root/pano-inpaint
bash deploy_powerpaint.sh
```

要求 `/root/iopaint-bench/inpaint_worker.py` 已在。PowerPaint 用 **Python 3.11** 旁路 venv（不要用 Demo 的 3.12）。

`server.env` 会被写成：

```
ENABLE_POWERPAINT=1
POWERPAINT_DEVICE=cuda
POWERPAINT_MAX_SIDE=768
IOPAINT_BENCH=/root/iopaint-bench
```

界面出现 PowerPaint 后，**第一次点才会加载约 4GB**（若未预热）。

---

## 4. 加 Qwen-Edit（24GB 卡才建议）

### 4.1 环境

清华源经常没有新版 `diffusers` / `bitsandbytes`。仓库里 `setup.sh` 会回退官方 PyPI。一律用 **`.venv/bin/python`**，不要只 `source activate` 后又退回 conda `(base)`。

```bash
cd /root/qwen-edit-bench
export HF_ENDPOINT=https://hf-mirror.com
chmod +x setup.sh
./setup.sh
.venv/bin/python -c "import torch; from diffusers import QwenImageEditPlusPipeline; print(torch.__version__, torch.cuda.is_available())"
.venv/bin/python smoke_cpu.py
```

期望：`True`，以及 `smoke_cpu ok`。

若 `bitsandbytes` 仍失败：

```bash
cd /root/qwen-edit-bench
.venv/bin/python -m pip install bitsandbytes -i https://pypi.org/simple
```

### 4.2 先预下载权重（不要用网页第一次加载）

130 上 Gradio 等 1800s 超时，下载被杀掉，随后 GPU 掉总线。129 上 **必须先下完再点界面**。

```bash
cd /root/qwen-edit-bench
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/root/qwen-edit-bench/.cache/huggingface
.venv/bin/python - <<'PY'
from huggingface_hub import snapshot_download
p = snapshot_download("seochan99/Qwen-Image-Edit-2511-bnb-nf4")
print("ok", p)
PY
```

下完再：

```bash
cd /root/pano-inpaint
bash deploy_qwen_edit.sh
```

写入：

```
ENABLE_QWEN_EDIT=1
QWEN_EDIT_DEVICE=cuda
QWEN_EDIT_MAX_SIDE=768
QWEN_EDIT_BENCH=/root/qwen-edit-bench
QWEN_EDIT_DRY_RUN=0
WARMUP_QWEN=0
WARMUP_POWERPAINT=0
```

### 4.3 第一次点 Qwen

另开终端：

```bash
journalctl -u pano-lama -f
watch -n 1 nvidia-smi
```

日志应有 `worker ready`，**不应**再出现 1800s 超时。PowerPaint 与 Qwen 会互斥卸载，不要两个一起预热。

## 5. 目标 `server.env`（启用后）

路径：`/root/pano-inpaint/server.env`

```bash
HOST=0.0.0.0
PORT=7860
INBROWSER=0
LAMA_DEVICE=cuda
SAM_DEVICE=cuda
ENABLE_POWERPAINT=1
POWERPAINT_DEVICE=cuda
POWERPAINT_MAX_SIDE=768
IOPAINT_BENCH=/root/iopaint-bench
ENABLE_QWEN_EDIT=1
QWEN_EDIT_DEVICE=cuda
QWEN_EDIT_MAX_SIDE=768
QWEN_EDIT_MARGIN=256
QWEN_EDIT_BENCH=/root/qwen-edit-bench
QWEN_EDIT_DRY_RUN=0
MAX_INFER_SIDE=2048
PREVIEW_MAX_SIDE=960
HF_ENDPOINT=https://hf-mirror.com
WARMUP=1
WARMUP_QWEN=0
WARMUP_POWERPAINT=0
```

显存不够时：`ENABLE_QWEN_EDIT=0`，只开 LaMa + PowerPaint。

改完：

```bash
systemctl restart pano-lama
```

## 6. 启用后验收

| 步骤 | 期望 |
|------|------|
| `nvidia-smi` | 有卡，服务起来后 SAM+LaMa 约占数 GB |
| 打开 `http://10.2.143.129:7860` | Radio：LaMa / PowerPaint / Qwen-Edit |
| 启动日志 | 预热 SAM、LaMa；**跳过** PowerPaint 与 Qwen |
| LaMa 消一张 | 数秒～十几秒，原分辨率 |
| PowerPaint | 首次 1～2 分钟，之后几十秒；ROI 768 |
| Qwen-Edit | 已预下载则 1～3 分钟加载，不要再下 15GB |
| `journalctl -u pano-lama -f` | 无 TimeoutError，无 `No NVIDIA GPU found` |

对比画质仍用同一批 Mask（见 `docs/三种修复模型对比报告.md`），Qwen 出图后补进对照。

## 7. 不要做的

- 不要把 Qwen / 新 diffusers 装进 `/root/pano-inpaint/.venv` 或 `/root/iopaint-bench/.venv`
- 不要对 6720 整图跑 PowerPaint / Qwen
- 不要 `WARMUP=1` 同时常驻 PowerPaint + Qwen
- 不要用网页当下载器去拉 Qwen 权重
- 不要执行 `do-release-upgrade`
- 不要从 130 拷半残的 `.cache/huggingface`
- 不要在 `nvidia-smi` 失败时继续点消除
